## What works

- `mergeLogin` preserves `mcpOAuth` and every other top-level key in the login
  item; only `claudeAiOauth` is replaced.
- `Credential.raw` carries the login branch verbatim; `refreshCredential`
  projects new tokens into it and refuses to give a legacy credential a
  passthrough it never had.
- `cuw add` records `account.uuid` and `email` from `/api/oauth/profile`, and
  fails closed (exit 2, nothing stored) when the profile cannot be read.
- `runUse` aborts before writing on every failure path: legacy credential,
  no login item, unidentifiable live login, no usable account, and a
  half-migrated registry.
- Verified against real data: `./dist/cuw use superclaude` exits 2 and the
  Keychain item is untouched afterwards (2 MCP servers, 7 login fields).

## Do this first — the migration

For each of `main`, `nimzo`, `superclaude`:

```
claude auth login        # for that subscription
cuw rm <id>
cuw add <id>
```

**The recurring trap** (documented in HOW-IT-WORKS.md and hit three times in a
previous session): if the browser still holds a claude.ai session, OAuth
auto-approves that account and the login silently lands on the wrong
subscription. Sign out first (`open https://claude.ai/logout`) or open the
printed authorize URL in a private window.

Verify after each add:

```
python3 -c "import json;print([a.get('uuid') for a in json.load(open('$HOME/.config/cuw/accounts.json'))])"
```

All three must show a uuid. Until they do, `cuw use` also refuses to capture an
untracked login — a half-migrated registry cannot tell "untracked" from
"tracked but never identified", and guessing wrong duplicates an account.

Once migrated, the first real switch is the only untested path left. Back the
item up before the first one:

```
security find-generic-password -s "Claude Code-credentials" -w > ~/cuw-login-backup.json
cuw use
# then confirm mcpOAuth survived:
security find-generic-password -s "Claude Code-credentials" -w \
  | python3 -c "import sys,json;d=json.load(sys.stdin);print(sorted(d), len(d.get('mcpOAuth',{})))"
```

Expect `['claudeAiOauth', 'mcpOAuth'] 2`. If `mcpOAuth` is missing or empty,
restore from the backup immediately and treat it as a P0 — that is the exact
failure the whole design exists to prevent.

## The finding that shaped the design

The `Claude Code-credentials` Keychain item is **not only the login**. It also
holds `mcpOAuth.<server>.accessToken` for every connected MCP server — on this
machine, Notion and Supabase. A naive `{claudeAiOauth: …}` overwrite would have
silently signed the user out of all of them, with no way back.

Two rules follow, and both are recorded as invariants in HOW-IT-WORKS.md:

1. **Never replace the item, only merge into it.** `mergeLogin` is the sole
   writer of `claudeAiOauth`.
2. **Store the branch verbatim.** cuw models four fields; the live branch has
   seven (`subscriptionType`, `rateLimitTier`, `refreshTokenExpiresAt`).
   Reconstructing from the typed subset drops the rest.

This is also why the migration cannot be automated: cuw never sees a full login
blob again after `add`.

## Design decisions worth not relitigating

These were settled with the user during brainstorming; the spec is at
`docs/superpowers/specs/2026-08-04-account-switching-design.md`.

- **Global switch**, not a per-shell `export`. It rewrites the Keychain item, so
  new `claude` sessions and the desktop app follow; running sessions do not.
- **On demand only.** No watcher, no daemon, no `SessionStart` hook. What is
  automated is the *choice* of account, not the timing. A hook calling
  `cuw use --quiet` remains the user's option to add.
- **Capture before overwrite.** An untracked active login is stored as a new
  account (id from the email local part) before being replaced.
- **Abort rather than guess.** If `/api/oauth/profile` fails for the live
  credential, the switch stops. Capture is the safety net for a destructive
  write, and the net depends on identification.

## Gotchas for whoever picks this up

- `runUse` takes the **raw** keychain (`createKeychain`), not the refreshing
  wrapper — it needs the credential blob, and `createRefreshingTokenSource`
  returns a bare access token. `cli.ts` has a comment saying so; do not
  "simplify" it to share the wrapper with `status`.
- `security` prints item attributes on **stdout**, not stderr. A quick zsh check
  suggested otherwise; that was a MULTIOS artifact. `login.ts` parses stdout.
- The login item's `acct` is read from the item itself, not hardcoded to
  `marty` — a machine whose login was created under another user name still
  works.
- `assertAccount` in `registry.ts` rebuilds the object field by field, so any
  new registry field must be added there explicitly or it is silently dropped
  on save.
- Codex usage reporting landed on `main` in parallel during this session and
  touched `cli.ts`, `constants.ts`, and `types.ts`. Re-read those before
  editing.
- `graphify-out/` is untracked and probably should be gitignored; left alone
  because it was not part of the task.
